Hacer preguntas sobre el libro de cátedra con distintas técnicas, en un mismo código, y compararlas.

Strands Agents · OpenRouter · Chroma + BM25 · Strands Evals

Seis técnicas, un chat para probarlas y evals para compararlas.

Objetivo: mostrar cómo cambia la respuesta según cómo se arma el contexto y quién decide qué buscar.

El problema: un LLM sin contexto inventa

Sin contexto

«¿Qué es un cubo?»

El modelo responde con lo que recuerda: genérico, sin fuente, a veces falso.

Con contexto

Buscamos fragmentos del libro y se los pasamos junto a la pregunta.

Respuesta anclada en el texto, con cita (archivo, p. N).

La pregunta del taller: ¿cómo conseguimos el mejor contexto?

Indexado: de PDF a índices

make setup   # deps + ollama pull embeddinggemma + .env
make index   # descarga el libro si falta · data/*.pdf → chroma_db/

Cada chunk guarda source y page para poder citar. Los PDFs no están en el repo: el libro es abierto (SEDICI, CC BY-NC-SA 4.0) y make data lo descarga; otro material de la cátedra hay que pedirlo.

Armado del contexto

Los chunks recuperados se numeran y se insertan en el prompt (RAG_PROMPT en techniques.py):

Respondé la pregunta usando SOLO el contexto. Si el contexto no alcanza, decí que no lo sabés.
Máximo tres oraciones, en español. Citá la fuente como (archivo, p. N).

CONTEXTO
{context}      # [1] (archivo.pdf, p. 45)\n texto del chunk ...

PREGUNTA: {question}

Con --show-context la CLI imprime los chunks y el prompt final de cada técnica. El chat los muestra en un desplegable.

técnica 1 · línea base

Sin contexto

Solo el conocimiento del modelo. Sirve para medir cuánto aporta el resto.

uv run tabi ask "¿Qué es un cubo?" -t no_context --show-context
técnica 2 · léxica

RAG con BM25

Coincidencia exacta de términos. Excelente con nombres propios y siglas; ciega a sinónimos.

uv run tabi ask "¿Quién es Ralph Kimball?" -t bm25 --show-context
técnica 3 · semántica

RAG vectorial (Chroma)

Busca por significado: encuentra «almacén de datos» aunque la pregunta diga «data warehouse».

uv run tabi ask "¿Para qué sirve un data warehouse?" -t vector --show-context
técnica 4 · híbrida

Ensemble: BM25 + vectorial (RRF 50/50)

Dos búsquedas: Chroma (la base vectorial) y BM25 (índice en memoria sobre los mismos chunks). Cada lista aporta peso / (60 + posición); se suman y quedan los 4 mejores. Mismo 50/50 que el repo 2024.

uv run tabi ask "¿Qué es una dimensión?" -t ensemble --show-context
técnica 5 · agente

Agente con tool de búsqueda

ensemble: pipeline fijo

Busca una vez con tu pregunta tal cual y responde en una sola llamada al modelo.

agent: el modelo decide

Usa ese mismo ensemble como herramienta, pero elige con qué texto buscar, cuántas veces y cuándo parar.

«¿En qué se diferencian Kimball e Inmon?» → el agente buscó Inmon enfoque top-down… y Kimball bus matrix… por separado.

make ask Q="¿En qué se diferencian Kimball e Inmon?" T=agent   # muestra consultas y chunks

Cada corrida de agent/multi guarda la conversación completa en tmp/conversations/ (ignorada por git).

Multi-agente: agents-as-tools

El cliente de chat

make chat   # Streamlit
  • Modelo: selector con todo el catálogo de OpenRouter
  • Técnicas: una o varias, lado a lado
  • Contexto: chunks, prompt armado, tools y consultas del agente
  • Índice: cuántos chunks hay y botón para indexar
  • Pestaña 📖 Técnicas: la explicación de cada una
  • Pestaña 🧪 Evals: cómo se mide y los últimos resultados

OpenRouter + Strands

Un solo cliente OpenAI-compatible: cambiar de modelo es cambiar un slug.

from strands.models.openai import OpenAIModel

OpenAIModel(
    client_args={"api_key": os.environ["OPENROUTER_API_KEY"],
                 "base_url": "https://openrouter.ai/api/v1"},
    model_id=os.getenv("TABI_LLM", "anthropic/claude-haiku-5.5"),
    params={"temperature": 0.1},
)
make models F=claude                               # lista/filtra el catálogo
make ask Q="..." T=agent M=openai/gpt-5-mini       # otro modelo en la CLI
make eval M=openai/gpt-5-mini                      # y también en los evals

La API key se carga con python-dotenv desde .env. Los embeddings siguen locales (Ollama).

Strands Evals: medir, no opinar

  • Case: 12 preguntas con respuesta esperada (2 fuera de tema)
  • Experiment: cada técnica corre sobre los mismos casos
  • correctness: LLM juez con rúbrica
  • faithfulness: ¿es fiel al contexto de la conversación?
  • relevance: ¿responde lo que se preguntó?
  • tool_called: ¿el agente usó la tool esperada? (sin juez)
exp = Experiment(
  cases=CASES,
  evaluators=[
    OutputEvaluator(rubric=RUBRIC, model=judge),
    FaithfulnessEvaluator(model=judge),
    ResponseRelevanceEvaluator(model=judge),
    ToolCalled("search_docs")])
report = await exp.run_evaluations_async(
    task, max_workers=4)

Fidelidad y relevancia leen las trazas OpenTelemetry de cada caso. Una línea de progreso por caso mientras corre.
